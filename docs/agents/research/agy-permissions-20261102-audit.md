# Ticket 158 audit: Antigravity CLI permissions

**Verdict: 8/10 — supported for the exact operations and Windows CLI build observed.** I cross-checked all 22 per-case settings, stdout tool events, stderr logs, and summaries in the repository-owned private probe, along with native history outputs and the actual external file bytes. The promoted record is [the native receipt](evidence/agy-permissions-20261102.json). The claims stay appropriately bounded to one host/account, one `agy` version, and tested targets. This is not evidence of OS sandbox containment or general command/path confinement.

## Weaknesses and limits

- An initial path check mistakenly searched system TEMP instead of the repository scratch directory; I corrected it and read the full 22-case bundle before completing this audit. Per-case stderr confirms the expected headless auto-denials on unmatched Ask actions; allow/deny outcomes are based on native tool events and outputs, not model response text.
- The committed receipt is a sanitized evidence summary, not a cryptographically signed raw run. Its recorded binary hash and global before/after hashes are claims within that receipt; I did not independently recompute the binary or historical settings hashes.
- The active docs were re-fetched on 2026-11-02 and their cited CLI sections match the guide. The TEMP claim appropriately relies on the dated 1.1.9 changelog entry. No source citation promises safety against shell/parser bypass, which the report also declines to claim.

No claim is unsupported. The unresolved Ask overlap is a reproduced **assertion failure**, not a documentation mismatch hidden by the report; follow-up belongs to #193 as stated.
